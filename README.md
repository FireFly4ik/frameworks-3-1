# Сервис формирования списка подарков

Локальный учебный проект для планирования подарков к событиям и контроля расходов. В ПР7 предметные данные перенесены из JSON в отдельную реляционную базу SQLite. Django получает данные прямыми SQL-запросами через стандартный модуль `sqlite3`; ORM на этом этапе намеренно не используется.

Консольная версия, объектная модель ПР3, шаблоны ПР6 и исходный файл `data/gifts.json` сохранены. JSON служит проверяемым источником для повторяемого импорта.

## Возможности

- просмотр подарков, получателей и событий в браузере;
- открытие карточек объектов по динамическим URL;
- поиск подарков по максимальной цене;
- отдельная страница агрегированной статистики;
- отображение связей `Gift → Occasion → Recipient` через SQL `JOIN`;
- расчёт количества, общего бюджета и статуса покупки средствами SQL;
- обработка пустых коллекций, неизвестных адресов и идентификаторов;
- работа прежнего консольного меню с JSON.

## Технологии

- Python 3.10+ и стандартный модуль `sqlite3`;
- SQLite, первичные и внешние ключи, индексы и ограничения `CHECK`;
- Django 5.2 LTS и Django Template Language;
- HTML, CSS, JavaScript и Bootstrap 5.3;
- pytest и pytest-django;
- flake8 и mypy в строгом режиме.

## Реляционная модель

Каждая предметная сущность хранится в отдельной таблице.

```text
gift_lists (1) ───────────────────────────── (*) gifts
                                                  │
recipients (1) ──── (*) occasions (1) ────────────┘
                       recipient_id          occasion_id
```

| Таблица | Назначение | Основные поля |
| --- | --- | --- |
| `gift_lists` | именованный список подарков | `id` PK, `name` |
| `recipients` | получатели | `id` PK, `name` |
| `occasions` | события получателей | `id` PK, `event_date`, `recipient_id` FK |
| `gifts` | подарки списка к событиям | `id` PK, `price`, `purchased`, `gift_list_id` FK, `occasion_id` FK |

Схема находится в `sql/schema.sql`. Для связей включается `PRAGMA foreign_keys = ON`; цена и статус покупки защищены ограничениями `CHECK`. Индексы добавлены для внешних ключей, даты события и цены.

## Импорт данных

Модуль `db/import_json.py` загружает `data/gifts.json` через существующую объектную модель, создаёт схему и переносит данные в `data/giftlist.sqlite`. Значения передаются параметрами `?`, а не подставляются в SQL-строки. Импорт выполняется транзакционно и может запускаться повторно без дублирования строк.

```bash
.venv/bin/python -m db.import_json
```

После импорта база содержит 1 список, 4 получателя, 5 событий и 8 подарков.

## SQL-запросы

Файл `sql/queries.sql` содержит 15 самостоятельных запросов:

- обычные выборки и сортировка;
- фильтрация `WHERE` по цене, статусу и дате;
- связи подарков, событий и получателей через `JOIN`;
- агрегаты `COUNT` и `SUM`;
- группировки по получателям, событиям и статусу;
- фильтрация групп через `HAVING`;
- подзапрос для получателей без купленных подарков.

В Python используется `sqlite3.Row`, поэтому шаблоны получают именованные поля. Динамические значения идентификаторов и бюджета во всех запросах передаются параметрами `?`.

## Django-страницы

| URL | Назначение |
| --- | --- |
| `/` | главная страница и краткая SQL-сводка |
| `/gifts/` | подарки с событиями и получателями через `JOIN` |
| `/gifts/affordable/?max_price=3000` | параметризованный поиск по бюджету |
| `/gifts/<id>/` | карточка подарка |
| `/recipients/` | получатели с количеством и стоимостью подарков |
| `/recipients/<id>/` | подарки выбранного получателя |
| `/occasions/` | события и связанные получатели |
| `/occasions/<id>/` | событие и его подарки |
| `/statistics/` | агрегированная статистика по списку и получателям |

Все предметные страницы читают `data/giftlist.sqlite`. Изменение данных через веб-интерфейс, Django ORM, формы и авторизация относятся к следующим практическим работам.

## Структура проекта

```text
.
├── db/                  # подключение SQLite и импорт JSON
├── sql/                 # схема и 15 проверяемых запросов
├── data/
│   ├── gifts.json       # исходные данные и консольное хранилище
│   └── giftlist.sqlite  # база предметной области ПР7
├── templates/           # общий шаблон, навигация и 404
├── giftservice/         # настройки и корневые URL Django
├── homepage/            # главная и страница статистики
├── gifts/               # список, карточка и поиск по бюджету
├── recipients/          # страницы получателей
├── occasions/           # страницы событий
├── models/              # объектная модель ПР3
├── tests/               # модель, импорт, SQL, консоль и Django
├── manage.py
├── main.py
└── storage.py
```

## Установка и запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m db.import_json
python manage.py migrate
python manage.py check
python manage.py runserver
```

Веб-интерфейс доступен по адресу `http://127.0.0.1:8000/`. Консольная версия запускается командой `python main.py`.

## Проверка

```bash
./scripts/check.sh
python manage.py findstatic homepage/img/logo.png
```

Скрипт запускает системную проверку Django, flake8, строгий mypy и pytest. Тесты подтверждают импорт четырёх сущностей, целостность и принудительное соблюдение внешних ключей, повторяемость импорта, результаты `JOIN` и агрегатов, параметризованный поиск, страницу статистики, ответы 404, шаблоны и static-файлы. Отдельный тест изменяет копию SQLite и доказывает, что веб-страницы читают базу, а не исходный JSON.
