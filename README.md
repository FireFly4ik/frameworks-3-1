# Сервис формирования списка подарков

Локальный учебный проект для планирования подарков к событиям и контроля расходов. В ПР5 консольная версия и объектная модель ПР3 сохранены, а данные из `data/gifts.json` представлены в веб-интерфейсе на Django 5.2.

## Возможности

- просмотр подарков, получателей и событий в браузере;
- открытие карточек объектов по динамическим URL;
- отображение связей `Gift → Occasion → Recipient`;
- вывод статуса покупки, даты события, цены и сводной статистики;
- обработка неизвестных адресов и идентификаторов с HTTP 404;
- работа прежнего консольного меню: добавление, поиск, фильтрация, сортировка, отметка покупки, удаление и расчёт бюджета;
- хранение данных между запусками в JSON.

Изменение данных через веб-интерфейс, Django ORM, формы и авторизация будут добавлены в следующих практических работах.

## Технологии

- Python 3.10+;
- Django 5.2 LTS;
- HTML, CSS и Bootstrap 5.3;
- pytest и pytest-django;
- flake8 и mypy в строгом режиме.

## Объектная модель

Каждая сущность находится в отдельном файле пакета `models`:

- `Recipient` (`models/recipient.py`) — получатель с идентификатором и именем;
- `Occasion` (`models/occasion.py`) — событие с датой и ссылкой на `Recipient`;
- `Gift` (`models/gift.py`) — подарок с ценой, статусом и ссылкой на `Occasion`;
- `GiftList` (`models/gift_list.py`) — агрегат, который хранит `Gift` и выполняет операции над списком.

```text
GiftList
└── Gift
    └── Occasion
        └── Recipient
```

Веб-слой использует ту же модель через `load_gifts()`. Данные не копируются в ORM и не дублируются во view-функциях.

## Django-приложения

- `homepage` — общий HTML-каркас, навигация, главная страница и обработчик 404;
- `gifts` — список и карточка подарка;
- `recipients` — список и карточка получателя;
- `occasions` — список и карточка события;
- `giftservice` — настройки и корневая маршрутизация проекта.

На этапе ПР5 HTML формируется view-функциями, как предусмотрено заданием. Общий каркас подключает Bootstrap 5.3 через CDN и содержит дополнительное CSS-оформление.

## URL веб-интерфейса

| URL | View-функция | Назначение |
| --- | --- | --- |
| `/` | `homepage.views.index` | главная страница и статистика |
| `/gifts/` | `gifts.views.gift_list` | список подарков из JSON |
| `/gifts/<id>/` | `gifts.views.gift_detail` | карточка подарка |
| `/recipients/` | `recipients.views.recipient_list` | список получателей |
| `/recipients/<id>/` | `recipients.views.recipient_detail` | подарки получателя |
| `/occasions/` | `occasions.views.occasion_list` | список событий |
| `/occasions/<id>/` | `occasions.views.occasion_detail` | карточка события |

Несуществующие ID и адреса возвращают код 404 и страницу в общем стиле проекта.

## Структура проекта

```text
.
├── giftservice/        # настройки, корневые URL, ASGI/WSGI
├── homepage/           # главная страница и общий HTML-каркас
├── gifts/              # страницы подарков
├── recipients/         # страницы получателей
├── occasions/          # страницы событий
├── models/             # объектная модель ПР3
├── data/gifts.json     # данные проекта
├── tests/              # тесты модели, хранения, консоли и Django
├── manage.py
├── main.py             # консольная версия
├── storage.py
└── requirements.txt
```

## Установка и запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py check
python manage.py runserver
```

После запуска веб-интерфейс доступен по адресу `http://127.0.0.1:8000/`. Консольная версия запускается отдельно:

```bash
python main.py
```

## Тесты и линтеры

Полная проверка проекта:

```bash
./scripts/check.sh
```

Скрипт последовательно запускает системную проверку Django, flake8, строгую проверку типов mypy и pytest. Отдельные команды:

```bash
python manage.py check
python -m flake8 .
python -m mypy --no-incremental .
python -m pytest -q
```
